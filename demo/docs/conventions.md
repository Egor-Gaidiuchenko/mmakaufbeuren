# Требования к коду

## TypeScript

- `strict`, `noUncheckedIndexedAccess`, `noFallthroughCasesInSwitch`.
- Тип пропсов называется `SomethingProps` и объявлен рядом с компонентом.
- Общие типы наружу слайса выходят через `index.ts`. Внутренний тип, который нужен только модулю, из слайса не экспортируется.
- `any`, `@ts-ignore` и ненулевое утверждение `!` в код не проходят. Если без исключения не обойтись, причина написана в описании пул-реквеста.
- Ошибка не проглатывается. Пустой `catch` заменяется на сообщение пользователю либо на проброс с причиной.

## React

- Компонент по умолчанию серверный.
- `"use client"` ставится на самый нижний компонент, которому нужны состояние, обработчик или браузерный API. Страница целиком клиентской не становится.
- Именованный экспорт. `export default` только у файлов Next.js: `page`, `layout`, `route`, `error`, `loading`, `not-found`.
- Файл компонента — `PascalCase.tsx`. Остальные файлы — `kebab-case.ts`.
- Один компонент на файл. Мелкий приватный кусок разметки может остаться в том же файле, пока его не импортирует сосед.
- Список рендерится со стабильным ключом предметной области, не с индексом массива.

## UI

- Вёрстка mobile-first: базовая раскладка для узкого экрана, расширение через `sm:` / `md:` / `lg:`.
- Стили — Tailwind. Произвольное значение (`w-[13px]`) допустимо, когда токена нет; повторившееся значение становится токеном в `globals.css`.
- На странице один `h1`.
- Кнопка — это `button`, ссылка — это `a` или `Link`. У обоих есть доступное имя.
- У поля формы есть связанный `label`. Ошибка поля связана с ним и видна без цвета как единственного носителя смысла.
- Картинки через `next/image`. Файлы клуба лежат в `public/` либо на разрешённом в `next.config.ts` хосте.
- Текст интерфейса на немецком. Временная главная показывает состав первой версии и будет заменена макетом.
- Часовой пояс клуба — `Europe/Berlin`. Форматирование даты живёт рядом с первым экраном и переезжает в `shared/lib`, когда появляется второй вызов.

## Импорты

- Алиас `@/` указывает на `src/`.
- Относительный импорт остаётся внутри одного слайса. Соседний слайс берётся только через публичный API и только если он лежит на слое ниже.
- Порядок: внешние пакеты, пустая строка, алиасы `@/`, пустая строка, относительные импорты.
- Циклический импорт между слайсами — повод поднять данные на страницу, а не завести `@x`. Связка `@x` между сущностями возможна после отдельного согласия в ревью.

## Git

- Ветка: `feature/<slug>` или `fix/<slug>`, в slug смысл изменения (`feature/schedule-page`).
- В пул-реквест входит один пользовательский результат. Рефакторинг соседнего слайса идёт отдельным запросом.
- Сообщение коммита говорит, зачем сделано изменение.
- Перед запросом локально проходит `npm run check`.
- Описание запроса: что изменилось для посетителя и какие маршруты затронуты.
- Ревьюер сначала смотрит слой и направление импортов, затем поведение и вёрстку.
- В `main` изменения попадают через пул-реквест.

Секреты, `.env*` и дампы с персональными данными в гит не коммитятся. Заявка на пробную тренировку — персональные данные: в лог пишется факт ошибки, не содержимое формы.

## Что считаем готовым

- Маршрут открывается с телефона и с ширины ноутбука.
- У страницы есть `metadata` и один `h1`.
- `npm run check` зелёный.
- Новый модуль импортируется так, как описано в `docs/architecture.md`.
- Пустой каталог слоя не добавлен «на вырост».
