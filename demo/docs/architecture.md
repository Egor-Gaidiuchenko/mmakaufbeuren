# Архитектура

Методология — [Feature-Sliced Design](https://feature-sliced.design/). Слои `app` и `pages` переименованы в `_app` и `_pages`, потому что у Next.js свои каталоги `app` и `pages` в корне.

## Слои

Импорт идёт только вниз.

| Слой | Каталог | Что здесь живёт |
| --- | --- | --- |
| App | `src/_app` | Провайдеры, глобальные стили, инфраструктурные route handler'ы |
| Pages | `src/_pages` | Сборка конкретного маршрута: разметка страницы, данные этой страницы, локальное состояние |
| Widgets | `src/widgets` | Крупный блок, который стоит на нескольких страницах или один закрывает целый сценарий экрана |
| Features | `src/features` | Действие пользователя: записаться на пробную, отфильтровать расписание |
| Entities | `src/entities` | Бизнес-сущность: тренер, дисциплина, тренировка, тариф |
| Shared | `src/shared` | Код без знаний о клубе: кнопки, клиент HTTP, даты, маршруты, env |

`processes` не создаём: в FSD слой устарел.

`_app` и `shared` без слайсов: сразу сегменты. Остальные слои сначала слайс, внутри него сегменты. Сегмент на корне нарезанного слоя (`features/ui`) запрещён.

Корневой `app/` — композиционный корень Next.js, не FSD-слой. Ему можно импортировать публичный API любого слайса. В нём нет бизнес-логики и запросов.

## Слайс и публичный API

```text
src/_pages/home/
  ui/home-page.tsx
  index.ts              только реэкспорты и metadata маршрута
```

Снаружи слайс существует как `@/_pages/home`. Путь `@/_pages/home/ui/home-page` закрыт ESLint-правилом `no-restricted-imports`. То же для `@/shared/config/routes`: снаружи доступен `@/shared/config`.

`index.ts` не содержит логики. Исключение — `metadata` страницы, её забирает файл маршрута:

```ts
export { HomePage as default, metadata } from "@/_pages/home";
```

Группы слайсов (`features/schedule/filter-schedule`) не используем, пока в слое меньше восьми слайсов. Текущий запрет глубоких импортов рассчитан на плоский список.

## Сегменты

Разрешённые имена: `ui`, `model`, `api`, `lib`, `config`.

| Сегмент | Содержимое |
| --- | --- |
| `ui` | Компоненты, их локальные стили |
| `model` | Состояние, схемы, правила предметной области |
| `api` | Запросы, server actions, маппинг ответа в тип слайса |
| `lib` | Функции слайса без UI и без запроса |
| `config` | Константы и настройки слайса |

Хуки лежат в `model` или `lib`. Типы лежат рядом с модулем, который их порождает. Отдельных папок `components`, `hooks`, `utils`, `types`, `store` нет.

## Когда заводить новый слайс

На старте почти весь код живёт в `_pages/<route>`. Вынос в `entities`, `features` или `widgets` делается, когда совпали все три условия:

1. Тот же код нужен минимум двум страницам.
2. У него одна понятная ответственность.
3. Дублирование уже мешает менять поведение в одном месте.

Похожая вёрстка на двух экранах сама по себе слайс не создаёт. Преждевременный `entities/coach` с одним потребителем хуже, чем модель тренера внутри страницы.

Обратный путь тоже нормальный: слайс, которым пользуется только одна страница, возвращается в эту страницу.

## Домен первой версии

Публичные маршруты собраны в `src/shared/config/routes.ts`.

| Маршрут | Слайс страницы | Что увидит посетитель |
| --- | --- | --- |
| `/` | `_pages/home` | Главная |
| `/training` | `_pages/training` | Направления |
| `/trainingsplan` | `_pages/trainingsplan` | Расписание |
| `/preise` | `_pages/preise` | Взносы |
| `/journal` | `_pages/journal` | Журнал |
| `/artikel` | `_pages/artikel` | Статья |
| `/probetraining` | `_pages/probetraining` | Запись на пробную тренировку |

Детальные маршруты добавляются вместе с данными, а не заранее: `/journal/[slug]`.

Сущности, которые появятся по мере вторых потребителей: `discipline`, `coach`, `training`, `membership`, `article`, `location`. Имена сущности в единственном числе.

Действия: `book-trial`, `filter-schedule`. Фильтр расписания хранится в URL, чтобы ссылка на день и дисциплину открывалась как есть.

Виджеты шапки и подвала (`site-header`, `site-footer`) появляются, когда оболочка нужна двум страницам. До этого оболочка остаётся в `app/layout.tsx` и на главной.

## Данные

- Читает данные серверный код сегмента `api`. Функция возвращает тип слайса и не возвращает JSX.
- Компонент в `ui` получает уже готовые пропсы.
- Пока клуб правит контент через деплой, источник — типизированные модули в `api` страницы. CMS и отдельный бэкенд подключаем, когда редактирование без выкладки станет требованием.
- Клиентский кэш (TanStack Query) добавляется в `RootProviders` вместе с первым экраном, которому он нужен. До этого провайдер только пропускает `children`.
- Redux Toolkit — клиентский стор слайса. `createSlice` и фабрика стора живут в `model`, `Provider` — в клиентском компоненте этого слайса. В `RootProviders` стор поднимается, когда то же состояние нужно двум страницам. Zustand не подключаем.

Форма записи на пробную: server action в `features/book-trial/api`, схема в `model`. Валидация на сервере обязательна даже при проверке на клиенте.

Секреты читаются только на сервере. В клиент попадает переменная с префиксом `NEXT_PUBLIC_`, и только через модуль `shared/config`. В компонентах `process.env` не читается.

## Next.js

Новая страница:

1. `src/_pages/<name>/ui` и `index.ts` с `metadata`.
2. `app/<route>/page.tsx` из одной строки реэкспорта.
3. Константа в `routes`.

Route handler: файл в `app/api/.../route.ts` реэкспортирует обработчик. Реализация живёт в слайсе, которому принадлежит действие. В `_app` остаются только служебные ручки вроде healthcheck.

`RootProviders` в `src/_app/composition` — единственное место для провайдеров темы, кэша и контекстов приложения. Провайдер одной фичи остаётся в этой фиче. Сегмент называется `composition`: Steiger не принимает имя `providers`.

Глобальные стили: `src/_app/styles/globals.css`, подключение относительным импортом из `src/_app/composition`. Токены цвета и шрифта задаются здесь. Тёмная тема включается отдельным решением, когда она есть в макете.

## Проверка границ

- ESLint не даёт импортировать внутренности слайса или сегмента.
- `npm run lint:fsd` запускает Steiger по `src/`.
- Правило `fsd/insignificant-slice` выключено: страницы импортирует корневой `app/`, и сканер по `src/` эти импорты не считает.
- `fsd/typo-in-layer-name` выключен: префикс `_` у `_app` и `_pages` правило считает опечаткой.
- Для `src/_app/styles` выключен `fsd/public-api`: сегмент — это один CSS-файл. Для `src/_app/composition` выключен `fsd/no-public-api-sidestep`, потому что этот сегмент подключает CSS относительным импортом.

Архитектурное замечание в ревью важнее замечания о стиле. Слайс, который смотрит вверх или вбок, не мержится.
